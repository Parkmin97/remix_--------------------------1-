## 3. 🔴 핵심 판정 — "설치된 앱" 은 왜 "수집 안 함" 인가

이 앱의 성패가 걸린 판정이므로 논리를 전부 적습니다.

**판정: `앱 활동 › 설치된 앱` = 수집하지 않음(No).**

**근거 1 — Play 의 "수집" 정의는 "기기 밖으로의 전송"입니다.** `[원문 확인 필요 — §6-1]`
데이터 보안 양식은 기기에서 읽는 것이 아니라 **개발자 서버 또는 제3자로 전송되는 것**을 신고하게 되어 있습니다. 기기 안에서만 처리되고 나가지 않는 데이터는 신고 대상이 아닙니다.

**근거 2 — 실제로 나가지 않습니다.**
- `AppListHelper.getLaunchableApps()` 의 반환값은 `BlockerPlugin.kt:73` 을 통해 웹뷰로 넘어가 **차단 대상 선택 화면에 그려지고 끝납니다.**
- Supabase 로 나가는 전체 페이로드는 `src/lib/supabase.ts` 의 3개 upsert 가 전부이며, **패키지명·앱 이름·앱 아이콘이 들어가는 필드가 하나도 없습니다.**
- 사용자가 고른 차단 대상 패키지 목록은 `BlockSessionStore` (SharedPreferences `MODE_PRIVATE`) 에만 남습니다.

**근거 3 — 권한 형태도 유리합니다.**
`QUERY_ALL_PACKAGES` 를 쓰지 않고 `<queries>` + LAUNCHER intent 만 선언했습니다 (`AndroidManifest.xml:144-149`). 제한된 권한(restricted permission) 신청서가 필요 없습니다. `[원문 확인 필요 — §6-3]`

**⚠️ 이 판정을 깨뜨리는 변경 (발생 즉시 양식 재제출 필요):**
1. 차단 대상 패키지명을 서버에 백업하는 기능
2. "가장 오래 쓴 앱 순위"를 서버에 저장하는 기능 (`정식출시.md:774` 에 미결정으로 남아 있음)
3. `syncLockHistoryToSupabase` 를 실제로 연결하는 것 → §5-1

**⚠️ 별도 리스크 (데이터 보안 양식과 무관하지만 심사에서 같이 걸립니다):**
`<queries>` 로 LAUNCHER 앱 전체를 조회하는 것이 **"앱 목록은 개인적이고 민감한 사용자 데이터"** 라는 Play 사용자 데이터 정책의 적용을 받는지는 별도 확인이 필요합니다. `[원문 확인 필요 — §6-3]` 이 경우 데이터 보안 신고 여부와 무관하게 **개인정보처리방침에 앱 목록을 읽는다는 사실과 그 목적을 명시**해야 합니다. → §4-2 에 반영했습니다.

## 5. ⚠️ 확인 필요 — 판단이 갈리는 회색지대

### 5-1. `syncLockHistoryToSupabase` — 정의돼 있으나 **한 번도 호출되지 않습니다**

`src/lib/supabase.ts:127-169` 에 잠금 이력 전송 함수가 있고 `lock_histories` 테이블에 `blocked_app_count`, `launch_attempts` 를 보내도록 짜여 있습니다. 그러나 `src/` 전체 grep 결과 **호출부가 없습니다** (정의 1건뿐).

- **현 시점 판정:** 실행되지 않으므로 신고 대상 아님.
- **위험:** 누군가 이 함수를 연결하는 순간, "차단 앱 개수"와 "차단된 실행 시도 횟수"가 서버로 나갑니다. 개수 자체는 `앱 상호작용`으로 이미 커버되지만, **§3의 "앱 사용 정보는 서버로 보내지 않는다"는 방침이 흐려집니다.**
- **권고:** 출시 전에 **이 함수를 삭제**하거나, 남긴다면 `// 의도적으로 호출하지 않음 — 데이터 보안 신고 범위 밖` 주석을 달아 잠그세요. **판정: 삭제 권고.**

### 5-2. `total_sns_minutes` — 스크린타임이 서버로 새어 나갈 통로

`src/lib/supabase.ts:103` 이 `total_sns_minutes` 를 `daily_reports` 에 씁니다. 그런데 `src/lib/storage.ts:83` 에서 `totalSnsMinutes: 0` 으로 만들어진 뒤 **어디서도 증가하지 않습니다.** 즉 **현재는 항상 0이 전송**됩니다.

- **현 시점 판정:** 실제 값이 없으므로 스크린타임 수집으로 보지 않음.
- **위험:** 이 필드를 `ScreenTimeHelper` 값으로 채우는 순간, **다른 앱 사용 시간에서 파생된 데이터가 서버로 나갑니다.** 이것이 `앱 활동 › 앱 상호작용`(내 앱 사용 정보)인지 `앱 활동 › 설치된 앱`(다른 앱 정보)인지가 **갈리는 지점**이며, 후자로 판정되면 §3의 핵심 방어선이 무너집니다.
- **권고:** **출시 전에 `syncDailyReportToSupabase` 의 페이로드에서 `total_sns_minutes` 를 제거**하세요. 항상 0인 필드를 위해 이 리스크를 질 이유가 없습니다. 채워야 한다면 그때 다시 판정받으세요.

### 5-6. 비밀번호는 신고 대상인가

Play 데이터 보안 양식에는 "비밀번호" 데이터 유형이 없습니다. 비밀번호는 Supabase 가 해시로 저장하며 개발자가 원문을 볼 수 없습니다. 별도 항목으로 신고하지 않고 **개인정보처리방침에만 기재**합니다. `[원문 확인 필요 — §6-1]`
