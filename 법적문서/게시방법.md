> **이 세션에는 웹 접근 도구가 없어 Play Console 화면과 각 호스팅 서비스의 최신 UI를 직접 열어보지 못했습니다.** 아래 절차 중 **메뉴 이름과 위치**는 변경되었을 수 있으므로 `[화면 확인 필요]` 표시가 붙은 항목은 실제 화면에서 대조해 주세요. 기술적 원리(무엇이 왜 필요한가)는 확정입니다.

## 0. 결론부터 — 만들어야 하는 URL은 3개입니다

| # | 무엇 | 왜 필요한가 | 어디에 쓰나 |
|---|---|---|---|
| **1** | **개인정보처리방침 URL** | Play Console 등록의 **필수 항목**. 없으면 앱을 올릴 수 없습니다 | Play Console 2곳 + 앱 안 1곳 |
| **2** | **이용약관 URL** | Play 필수는 아니지만, 앱 안에서 "서비스 이용약관 및 개인정보처리방침"이라고 안내하고 있으므로 실제로 존재해야 합니다 | 앱 안 1곳 |
| **3** | **계정 삭제 요청 URL** | 계정 생성을 받는 앱에 Play가 **별도로 요구**하는 항목. 앱 내 삭제 기능과 **둘 다** 있어야 합니다 `[원문 확인 필요]` | Play Console 1곳 + 개인정보처리방침 본문 |

**가장 간단한 구성:** 페이지 3개를 각각 만들거나, **한 페이지 안에 세 개의 섹션을 두고 앵커(`#`)로 나누는 방식**도 가능합니다. 다만 **Play Console에 넣는 개인정보처리방침 URL은 열자마자 개인정보처리방침이 보여야 하므로**, 최소한 개인정보처리방침만은 독립된 페이지로 두시길 권합니다.

## 1. 어디에 게시할 것인가 — 선택지 비교

| 방법 | 난이도 | 비용 | 수정 편의 | 권장도 |
|---|---|---|---|---|
| **A. GitHub Pages** | 중 | 무료 | 좋음 (파일 수정 후 푸시) | ⭐ **권장** — 이미 이 프로젝트가 git 저장소이고, 문서가 마크다운이며, URL이 영구적입니다 |
| **B. Notion 공개 페이지** | 하 | 무료 | 매우 좋음 | 가장 빠름. 마크다운 붙여넣기가 그대로 됩니다 |
| **C. Google Sites** | 하 | 무료 | 보통 | 표 서식이 깨지기 쉽습니다 |
| **D. 자체 도메인 + 정적 호스팅(Vercel/Netlify)** | 상 | 무료~ | 좋음 | 도메인이 이미 있다면 가장 깔끔합니다 |

**어느 방법을 쓰든 반드시 만족해야 하는 조건 (Play 심사에서 실제로 확인합니다):**

1. **로그인 없이** 열려야 합니다 (심사관은 로그인하지 않습니다)
2. **PDF 다운로드가 아니라 웹페이지**여야 합니다
3. **누구나 편집할 수 있는 문서면 안 됩니다** (구글 문서를 "편집 가능"으로 공유하면 안 됩니다)
4. 모바일 브라우저에서 정상적으로 읽혀야 합니다
5. 앱 이름 또는 패키지명(`com.mylifemaestro.app`)이 문서 안에 나와야 합니다 — **작성한 문서에 이미 들어 있습니다**

## 2. 방법 A — GitHub Pages (권장)

### 2-1. 어느 저장소에 둘 것인가

앱 소스 저장소에 두어도 되지만, **법적 문서 전용 공개 저장소를 따로 만드는 편**을 권합니다. 앱 소스가 비공개인데 문서만 공개해야 하는 상황이 흔하고, 저장소를 나누면 소스 공개 여부와 무관해집니다.

```
새 저장소 이름 예: mylifemaestro-legal   (Public 으로 생성)
```

### 2-2. 절차

**① 파일 준비**

새 저장소에 아래 구조로 파일을 넣습니다.

```
mylifemaestro-legal/
├── index.md          ← 두 문서로 가는 링크 목록
├── privacy.md        ← 개인정보처리방침 (자리표시자를 모두 채우고, 0장·부록 삭제)
├── terms.md          ← 이용약관 (자리표시자를 모두 채우고, 0장·부록 삭제)
└── delete-account.md ← 계정 삭제 요청 안내 (§4 참조)
```

**⚠️ 반드시 각 문서의 「0. 게시 전 반드시 채워야 할 항목」 장과 문서 맨 뒤의 부록을 삭제한 뒤 올리세요.** 부록에는 개발팀 내부용 지적사항이 들어 있어 그대로 공개하면 곤란합니다.

**② 각 파일 맨 위에 아래 4줄을 추가합니다** (GitHub Pages가 제목과 목차를 만들어 줍니다)

```yaml
---
layout: default
title: 개인정보처리방침
---
```

**③ Pages 활성화** `[화면 확인 필요]`

```
저장소 → Settings → Pages
→ Source: "Deploy from a branch"
→ Branch: main / (root)  → Save
```

**④ 테마 지정 (선택이지만 권장)** — 저장소 루트에 `_config.yml` 파일을 만들고 아래 한 줄을 넣으면 마크다운 표가 읽기 좋게 렌더링됩니다.

```yaml
theme: jekyll-theme-minimal
```

**⑤ 1~2분 뒤 아래 주소로 접속됩니다**

```
https://<깃허브계정명>.github.io/mylifemaestro-legal/privacy
https://<깃허브계정명>.github.io/mylifemaestro-legal/terms
https://<깃허브계정명>.github.io/mylifemaestro-legal/delete-account
```

> `.md` 확장자는 붙이지 않습니다. Jekyll이 `privacy.md` → `/privacy` 로 변환합니다.

### 2-3. GitHub Pages를 권하는 이유

- URL이 바뀌지 않습니다 (Play Console에 등록한 뒤 URL이 바뀌면 재심사 사유가 됩니다)
- 문서 수정 이력이 git에 남습니다 — **개인정보처리방침은 변경 이력을 증명할 수 있어야 유리합니다**
- 서버 관리가 필요 없고 만료되지 않습니다

## 3. 방법 B — Notion 공개 페이지 (가장 빠름)

### 3-1. 절차 `[화면 확인 필요]`

1. Notion에서 새 페이지를 만들고 제목을 **"내인생 지휘자 개인정보처리방침"** 으로 합니다
2. `개인정보처리방침.md` 의 **본문만**(0장과 부록 제외) 복사해 붙여넣습니다. **Notion은 마크다운을 붙여넣으면 표와 제목을 자동으로 변환합니다**
3. 자리표시자(`{{...}}`)를 모두 실제 값으로 바꿉니다. `{{` 로 검색해 하나도 남지 않았는지 확인하세요
4. 우측 상단 **공유(Share) → 웹에 게시(Publish to web)** 를 켭니다
5. **아래 두 개는 반드시 꺼 두세요**
   - `편집 허용(Allow editing)` — **켜져 있으면 누구나 방침을 고칠 수 있어 심사에서 문제가 됩니다**
   - `댓글 허용(Allow comments)` — 켤 이유가 없습니다
6. `검색 엔진 색인(Search engine indexing)` 은 켜도 무방합니다
7. 생성된 URL을 복사합니다
8. 이용약관·계정 삭제 안내 페이지도 같은 방식으로 만듭니다

### 3-2. Notion을 쓸 때 확인할 것

| 확인 | 방법 |
|---|---|
| **로그인 없이 열리는가** | 브라우저 **시크릿 창**에서 URL을 열어 확인. 로그인 화면이 뜨면 게시 설정이 안 된 것입니다 |
| **URL이 안정적인가** | Notion은 페이지 제목을 바꾸면 URL의 앞부분이 바뀝니다(뒤의 32자리 ID는 유지). **Play에 등록한 뒤에는 페이지 제목을 바꾸지 마세요** |
| **워크스페이스를 삭제하지 않는가** | Notion 계정이나 워크스페이스를 정리하면 URL이 죽습니다. **URL이 죽으면 앱이 스토어에서 내려갈 수 있습니다** |
| `[원문 확인 필요]` | Notion 공개 페이지가 Play 심사에서 문제없이 통과되는지는 이 세션에서 확인하지 못했습니다. 심사관이 JavaScript 없이 접근하는 경우를 대비하면 **GitHub Pages 쪽이 더 안전합니다** |

## 4. 계정 삭제 요청 페이지에 들어가야 할 내용

```markdown

잠금이 실행 중일 때는 탈퇴할 수 없습니다.
잠금 시간이 끝나거나 지휘 미션에 성공한 뒤 진행해 주세요.

## 방법 2 — 이메일로 요청하기

앱을 이미 삭제하셨거나 앱에 접속할 수 없는 경우,
```

## 6. 앱 코드 수정 — `SettingsScreen.tsx`

### 6-1. 현재 상태

`src/components/SettingsScreen.tsx:7`

```ts
const PRIVACY_POLICY_URL = '/privacy_terms.pdf';
```

앱 내부에 번들된 PDF를 여는 경로입니다. **이대로 두면 안 됩니다.** 심사관은 Play Console에 등록된 웹 URL과 앱 안의 링크가 같은 문서를 가리키는지 확인합니다.

### 6-2. 최소 수정 (URL만 교체)

```ts
/** 개인정보처리방침 공개 웹페이지 주소. Play Console에 등록한 것과 동일해야 한다. */
const PRIVACY_POLICY_URL = 'https://<게시한 주소>/privacy';
```

### 6-3. 권장 수정 (약관과 방침을 분리)

현재 버튼 하나가 **"서비스 이용약관 및 개인정보처리방침"** 이라는 두 문서를 가리키고 있습니다. 문서가 두 개로 나뉘었으므로 항목도 둘로 나누는 편이 정확합니다.

```ts
/** 개인정보처리방침 공개 웹페이지. Play Console 등록 주소와 반드시 동일. */
const PRIVACY_POLICY_URL = 'https://<게시한 주소>/privacy';
/** 서비스 이용약관 공개 웹페이지. */
const TERMS_OF_SERVICE_URL = 'https://<게시한 주소>/terms';
```

기존 버튼을 복제해 두 개로 만들고, 각각 `handleOpenPrivacyPolicy` / `handleOpenTerms` 를 연결하면 됩니다.
**이 파일은 ui-designer 소유이므로 실제 수정은 해당 담당이 진행하는 것이 맞습니다.**

### 6-4. ⚠️ 반드시 실기기에서 확인할 것

이 앱은 Capacitor WebView 앱입니다. `window.open(url, '_blank')` 로 **외부 https 주소**를 여는 동작이 실제 기기에서 어떻게 되는지 확인해야 합니다.

| 결과 | 판정 |
|---|---|
| 시스템 브라우저(또는 Custom Tab)가 열린다 | ✅ 정상 |
| **앱 안의 WebView가 그 주소로 이동해 버리고 뒤로 갈 수 없다** | 🔴 **치명적.** 이용자가 앱에 갇힙니다 |
| 아무 일도 일어나지 않는다 | 🔴 심사에서 "링크가 동작하지 않음"으로 걸립니다 |

두 번째·세 번째가 나오면 **`@capacitor/browser` 플러그인**(현재 `package.json`에 없습니다)을 추가해 `Browser.open({ url })` 로 바꾸거나, `capacitor.config.ts` 에 외부 URL 처리 설정을 추가해야 합니다.
→ **android-native-engineer / release-qa 확인 항목입니다.**

### 6-5. 기존 PDF 정리

`public/privacy_terms.pdf` 와 `public/privacy_policy, terms_of_service.pdf` 두 개가 있습니다.

- **두 번째 파일은 파일명에 쉼표와 공백이 있어 URL 인코딩 사고를 부릅니다. 삭제를 권합니다.**
- 웹 게시로 전환한 뒤에는 두 PDF 모두 앱 번들에서 제거해도 됩니다. 다만 **앱 안에서 오프라인으로도 약관을 볼 수 있게 남겨두는 선택**도 가능합니다. 남긴다면 **PDF 내용과 새 웹 문서의 내용이 서로 다르면 안 됩니다.**
- ⚠️ **현재 두 PDF의 본문은 압축되어 있어 이 세션의 도구로는 텍스트를 추출하지 못했습니다.** 새 문서와 어긋나는 내용이 있는지 **사람이 직접 열어서 대조**해야 합니다. 대조하지 않을 것이라면 **삭제하는 편이 안전합니다.**

## 7. Play Console에 URL을 넣는 위치

`[화면 확인 필요]` **콘솔 메뉴 이름은 수시로 바뀝니다. 아래와 다르면 실제 화면을 우선하세요.**

| # | 넣는 곳 | 경로 | 무엇을 넣나 |
|---|---|---|---|
| **1** | **앱 콘텐츠 → 개인정보처리방침** | Play Console → 앱 선택 → 좌측 `정책 및 프로그램` → `앱 콘텐츠` → `개인정보처리방침` | 개인정보처리방침 URL |
| **2** | **데이터 보안 양식 안** | `앱 콘텐츠` → `데이터 보안` 진행 중 개인정보처리방침 URL을 다시 묻습니다 | **1번과 완전히 같은 URL** |
| **3** | **앱 콘텐츠 → 데이터 삭제** | `앱 콘텐츠` → 데이터/계정 삭제 관련 항목 | 계정 삭제 요청 URL + "앱 내에서도 삭제 가능"에 체크 |
| **4** | **스토어 등재정보 → 개발자 연락처** | `성장` → `스토어 설정` 또는 `기본 스토어 등재정보` 내 개발자 연락처 | 이메일 — **개인정보처리방침의 {{문의이메일}}과 같은 주소로 통일하세요** |

### 7-1. 흔히 놓치는 것

- **1번과 2번의 URL이 한 글자라도 다르면 안 됩니다.** 끝의 `/` 유무까지 맞추세요.
- 개인정보처리방침 URL은 **앱을 심사에 제출한 뒤에도 계속 살아 있어야 합니다.** 심사 통과 후 페이지를 지우면 정책 위반입니다.
- 앱 안의 링크(§6)와 Play Console의 URL이 **같은 문서**를 가리켜야 합니다.
- 데이터 보안 양식의 답변과 개인정보처리방침 본문이 **모순되면 거절 사유입니다.** 대조 결과는 `_workspace/release_compliance_datasafety.md` 와 함께 확인하세요.
